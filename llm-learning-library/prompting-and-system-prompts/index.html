Prompting and System Prompts

Prompting is the main way developers shape model behavior at runtime. Good prompts clarify goals, constraints, context, and output format.

Rule of thumb

Prompt first. If the task can be fixed by clearer instructions or better context, do that before considering training changes.

Instruction hierarchy

System prompt

Global behavior, role, and safety constraints.

Application prompt

Workflow-specific rules, tools, and schemas.

User prompt

The task request and user-provided information.

Prompt design patterns

  • Zero-shot instructions for known tasks.
  • Few-shot examples when formatting matters.
  • Structured delimiters to separate context and instructions.
  • Explicit constraints and evaluation reminders.
If the model lacks facts, use RAG. If it needs action in the world, use tools or agents. If it needs durable narrow behavior, consider fine-tuning.
