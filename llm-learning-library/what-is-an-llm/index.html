Foundations

What an LLM Is

A large language model is not a database, a person, or a magic reasoning engine. At its core, it is a neural network trained to predict the next token in a sequence. That simple objective, scaled up far enough, produces surprisingly broad language behavior.

Predicts next tokenLearns statistical structureWrapped in software systems

Core claim

If you understand next-token prediction, context, and learned representations, the rest of the LLM stack becomes much easier to reason about.

The shortest useful definition

An LLM is a very large neural network that has been trained on vast text-like data so it can continue a sequence one token at a time. During training it compresses patterns of language, facts, style, structure, and correlations into its weights. During use, it reads your prompt, computes probabilities for what should come next, samples or chooses the next token, appends it, and repeats.

Why "language model"? Because it models the probability distribution of token sequences. "Large" mainly refers to parameter count, training data scale, and compute budget.

Why this simple objective becomes powerful

Compression of patterns

To predict well, the model must absorb grammar, syntax, facts, topic structure, code conventions, and latent relationships between concepts.

Scale changes behavior

Small models memorize shallow patterns. Large models, trained broadly, begin showing abstraction, transfer, and more coherent multi-step outputs.

Instruction tuning matters

The raw model predicts text. Chat behavior usually comes later, through instruction tuning, preference optimization, safety tuning, and system-level scaffolding.

Main limits to remember

LimitWhy it happensPractical consequence
HallucinationThe model generates plausible text even when evidence is missing.You need retrieval, verification, or evaluation loops for factual tasks.
Context dependenceThe model only sees the prompt window, not the whole world.Prompt quality and context management strongly affect performance.
No durable memory by defaultEach call is usually stateless unless the application stores history.Applications must explicitly manage memory, documents, and user state.
Training cutoffs and biasKnowledge reflects its training distribution and later tuning choices.Fresh data and domain grounding often require RAG or fine-tuning.
